## ما وُجد وما اكتمل

| البند | الحالة القابلة للمراجعة |
|---|---|

| Design QC — B05/B06/B09 | الموجود اجتاز الموافقة والرفض والتجاوز المسبب، منع تجاوز نفس الملفات المرفوضة، ورفض لاحق بعد تجاوز ينبه المنسق ولا يوقف الإنتاج آليًا |
| إيقاف QC | سويتش أدمن مستمر حتى إعادة التشغيل يدويًا، بلا اعتماد أو مراجعة بأثر رجعي؛ صُلح تحديث حالة الحالة المفتوحة فور تغيير السويتش |
| إعادة تكليف المصمم | الموجود اجتاز اختيار مستحق السابق وأجر البديل الافتراضي أو اليدوي، مع بقاء حق السابق المالي وفقده الوصول للحالة والملفات؛ لا تعديل لحركة النقد |
| استحقاق المورد الطبيعي — الحزمة 3 | التعديل المحلي الموجود عند `final_delivered` أعيد اختباره. لا تغيير لاستحقاق المصمم عند إتمام التصميم، أو النقد أو الـRemake. لم يُنقل هذا إلى الإنتاج |
| فقرة المورد الفنية — B10، E05؛ الحزمة 8 | أضيفت: فقرة موحدة، مصدر خاص للأدمن، مرفقات خاصة بأسماء عشوائية، نسخ محفوظة وحالات تجريبي/معتمد/متوقف؛ مراجعة صريحة لإخفاء هوية المورد قبل الحفظ |
| ربط الفقرة بالتسليم | كل تسليم جديد يحفظ رقم نسخة التعليمات وقتها؛ تعديلها لاحقًا لا يغير الماضي ولا يبطل موافقة ملفات التصميم. غيابها/إيقافها ظاهر ولا يمنع التسليم تلقائيًا |
| خصوصية المصمم — B14، E06 | أضيفت إسقاطات API بقائمة حقول فنية/مستحقات شخصية صريحة، ومنع القراءة الخام للطلبات وأسعار البنود والموردين والأطباء والمصادر التجارية والسجلات التجارية؛ ملف المستخدم الشخصي فقط؛ منع RPC لوحة المؤشرات التجارية القديم من تجاوز ذلك |
| ملفات وتاريخ وكاش | منع قراءة/توقيع ملفات Scan لحالات الآخرين، ومنع السابق بعد إعادة التكليف؛ البديل يرى التاريخ الفني المطلوب. أزيل كاش المصمم التجاري القديم وكاش اللوحة العامة، وصارت الصفحة الرئيسية للمصمم مسارًا فنيًا مستقلًا؛ تحديث عند التركيز وكل 30 ثانية |
| توافق حالات التصميم القديمة | اختبار فعلي كشف أن قيد قاعدة البيانات كان يقبل ثلاث حالات فقط، بينما الواجهة وRPC يستخدمان ستًا. القيد الآن يقبل الست المعتمدة ويمنع القيم المختلقة؛ سبب طلب رفض المصمم يسجل ذريًا مرة واحدة، دون مسار أو قرار مالي جديد |

صلاحيات الأدمن والمنسق وبقية الأدوار التشغيلية باقية؛ التضييق التجاري يخص دور المصمم الأساسي. أصحاب الأدوار المزدوجة يحتفظون بصلاحيات دورهم التشغيلي المستقلة. لا طابور موافقات مالية جديد، ولا تغيير لمعنى `approved`.

## التحقق

- **58 ملف SQL / 1082 تحقق PASS** من سلسلة مهاجرات جديدة على `design-qc-qa` المملوكة للاختبار فقط، API `56501` وDB `56502`. يشمل ذلك الاختبارات الموجودة للأموال والشحن والتكلفة والـRemake وQC، مع اختبارات النسخ والصلاحيات الجديدة.
- **67 ملف Unit / 588 اختبار PASS**؛ اختبارات الأوامر أضيف لها دور المستخدم ورفض الرجوع للقراءة الخام عند فشل تحديد الدور.
- **3 اختبارات متصفح PASS** على Chrome بواجهة مبنية ومصادقة وStorage وRPC محلية حقيقية، دون استبدال صلاحيات الخادم بم mocks: حفظ فقرة المورد ورفع مرفق فعلي؛ المصمم والكاش؛ التشغيل/الإيقاف؛ الملفات والموافقة والرفض والتجاوز والتسوية؛ عزل HTML عند 375 و1280 بكسل.
- TypeScript/Build PASS. `npm run lint` بلا أخطاء؛ تحذيران سابقان في `DashboardNew.tsx` عن dependencies، خارج التغيير. استُبعدت مجلدات QA والبناء والنسخة المنفصلة المولدة من ESLint، لا ملفات التطبيق.
- فحص إضافي لحسابات المراجعة على `5173`: الأدمن يرى الإصدار الحالي والسابق؛ مستحق المصمم الشخصي 100 جنيه ظاهر؛ المورد ومصدره الخاص مخفيان؛ السويتش عاد للإيقاف.
- RED محفوظ في commits `67919a8b`، `8403cec2`، `9af2b1f5`، `2251bc55`، `b336895b`؛ سجلات GREEN ولقطات المتصفح تحت `.tmp/day2-*` و`.tmp/design-qc-*`. أخطاء صياغة أولية في اختبار CTE وحارس حذف Storage عولجت دون تخفيف سياسات الحماية؛ اختبار الحذف يستخدم إعداد خدمة Storage داخل transaction يتراجع بالكامل لكي يتحقق من RLS نفسها.

الـQA الجديدة تجمع التعديلات المحلية الموجودة، ومنها أعمال دمج سابقة غير منشورة. نجاحها ليس تصريحًا بنشر كل هذه التعديلات أو كل المهاجرات الناقصة من الإنتاج.

## افتح وراجع

افتح [نسخة المراجعة المحلية](http://127.0.0.1:5173/login). لو كانت جلسة قديمة مفتوحة، سجّل خروجًا ثم ادخل لأن تشغيل الاختبارات أعاد إنشاء QA. كلمة المرور للحسابات التجريبية فقط: **`Local-Review-2026!`**.

| الحساب | الاستخدام |
|---|---|
| `review_admin` | الفقرة الخاصة بالمورد، المصدر، السويتش، القرارات والتسوية |
| `review_coordinator` | المتابعة والتجاوز المسبب والإعادة، دون سلطة تشغيل السويتش أو اعتماد/رفض الأدمن |
| `review_designer_old` | الحالات المكلف بها والمستحق الشخصي |
| `review_designer_new` | التحقق من انتقال الصلاحيات بعد إعادة التكليف |
| `review_accountant` | المراجعة المالية المحلية |

1. افتح [الموردين](http://127.0.0.1:5173/suppliers)، وعدّل **معمل تجريبي للمراجعة**: راجع الفقرة وإصداراتها والمصدر الخاص وتأكيد الخصوصية.
2. افتح [DAY2-REVIEW-2](http://127.0.0.1:5173/design-qc?order=fd000000-0000-4000-8000-000000000102): الفقرة الحالية أحدث، والفقرة المحفوظة مع التسليم هي السابقة. جرّب فتح المعاينة وتحميل نسخة التنفيذ.
3. السويتش **موقوف** عند التسليم لك. شغّله كأدمن بسبب واضح، ثم افتح [DAY2-REVIEW-1](http://127.0.0.1:5173/design-qc?order=fd000000-0000-4000-8000-000000000101) وسلّم نسخة جديدة لتجربة إلزام المراجعة. لا يُفرض على النسخة السابقة بأثر رجعي.
4. الملفات الاصطناعية الجاهزة للرفع: `scratch/day2-review-fixtures/execution.zip` و`preview.html`. ZIP فارغ اصطناعي صالح لاختبار المسار؛ لا تستخدمه للتنفيذ الفني.
5. جرّب الموافقة، ثم ملفات معدّلة ورفضها. محاولة تجاوز الملفات نفسها يجب أن تُرفض. نسخة معدّلة جديدة تقبل تجاوز المنسق بسبب؛ رفضها لاحقًا يترك المتابعة ظاهرة.
6. في إعادة التكليف: حدد مبلغ السابق، واختر البديل، واترك أجره الافتراضي أو غيّره يدويًا. ادخل بالمصمم السابق للتحقق من فقد فتح الحالة مع بقاء المستحق، ثم بالبديل للتحقق من التاريخ الفني فقط. صفحة [الحسابات](http://127.0.0.1:5173/accounts?tab=designers) للمستحقات الشخصية.

إعادة تجهيز أمثلة المراجعة بعد أي reset للاختبارات: `pwsh -NoProfile -File scripts/day2-local-review.ps1`. السكربت يتحقق من علامة ملكية QA وAPI المحلي، ولا يستهدف المشروع المحلي الأساسي أو الإنتاج، ولا يفتح السويتش.

## الباقي وحدود الاعتماد

- **بوابة خارجية مفتوحة:** لا توجد عينة exocad حقيقية في الملفات المتاحة. المعاينة الاصطناعية تثبت العزل ومسار الرفع، ولا تثبت توافق ملفات exocad الفعلية أو تجربة جهازك. مراجعة عينة حقيقية على الموبايل والديسكتوب مطلوبة قبل اعتبار هذه البوابة مقفولة.
- لا يمكن سحب نسخة ملف سبق تنزيلها أو رابط خارجي قديم من شخص اطلع عليه. المنع يخص الطلبات الجديدة وتوقيع الملفات الخاصّة؛ الروابط الموقعة السابقة تعمل حتى انتهاء صلاحيتها. لا نسخ تاريخي أو تغيير صلاحيات تخزين الإنتاج أو معالجة روابط قديمة ضمن هذا العمل.
- تجهيز إنتاج اليوم الثاني يتطلب اختيار حزمة متوافقة ومراجعتها مقابل مخطط الإنتاج الحالي والمهاجرات القديمة غير الموجودة به، ثم موافقة منفصلة. لا تطبيق آلي لكل المهاجرات ولا backfill.
- Try-In وPhysical QC/Shipping Ready والإشعارات المركزية وبقية الشحن والتكلفة تتبع الحزم اللاحقة 6/7/10/11/12/13؛ ليست جزءًا منشورًا ضمن اليوم الأول، ولا يُعتبر وجودها بالخطة دليلًا على تنفيذها.
