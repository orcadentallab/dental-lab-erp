# رفع التصميم بالسحب والإفلات وإصلاح ZIP ويندوز

- منطقتان منفصلتان لـ ZIP وHTML في نموذج التسليم المشترك، مع اختيار بالضغط ولوحة المفاتيح، وإظهار اسم الملف واستبداله، وتعطيل أثناء الحفظ. يدعم الإسقاط ملفًا واحدًا لكل منطقة ويتحقق من الامتداد والحجم (ZIP 50MB، HTML 10MB).
- سبب خطأ `application/x-zip-compressed`: مكتبة Storage تستعمل نوع Blob داخل multipart، ولا يكفي خيار contentType. يُرسل الآن Blob بنفس البايتات ونوع MIME القياسي لكل ملف، في المسارين القديم والجديد، دون توسيع سياسة التخزين أو تغيير مالي أو مهاجرة.
- اختبار unit فشل أولًا على MIME الحقيقي ثم نجح بعد الإصلاح؛ المجموعة 71 ملفًا / 600 اختبار ناجحة.
- اختبار Chrome على QA المعزولة: رفض إسقاط TXT، إسقاط ZIP بنوع ويندوز وHTML، الحفظ الفعلي، ثم عرض HTML المحفوظ بنجاح. الحالة الاصطناعية المضافة فقط `DAY2-UPLOAD-DROP`؛ لم تُصفّر QA أو تُعدّل حالات المراجعة السابقة.
- اختبار المتصفح الدائم للتسليم أثناء إيقاف QC يستخدم السحب بدل الاختيار، ويتحقق من رفض امتداد خاطئ قبل الحفظ؛ بقية الاختبارات تحتفظ بتغطية الاختيار بالضغط.
- build ناجح؛ lint بلا أخطاء مع تحذيري DashboardNew السابقين. لم تُعد مجموعة SQL لعدم وجود تغيير قاعدة بيانات، ولم تُعد المجموعة المتكاملة التي تصفّر بيانات QA حفاظًا على تجارب المالك الحالية.

محلي فقط؛ لا نشر أو إنتاج أو تعديل مفتاح QC. الأدلة المحلية `.tmp/upload-red.log`، `.tmp/upload-green.log`، `.tmp/upload-unit.log`، `.tmp/upload-build.log`، `.tmp/upload-lint.log`، `.tmp/upload-drop-pass.png`.
