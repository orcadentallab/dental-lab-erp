## الحزمة المعزولة

`output/doctor-portal-release/doctor-portal.patch` يحتوي تغييرات البوابة فقط بالنسبة إلى HEAD، ولا يتضمن `.env` أو تغييرات التقارير الأخرى. يراجع ثم يطبق على checkout مستقل لنفس HEAD، بدل نشر شجرة العمل الحالية بكاملها. ملف `manifest.txt` يوضح الملفات المشمولة. يجب إعادة توليد الحزمة عند تعديل الكود بعد تاريخ التحقق.

## التحقق قبل إطلاق الأطباء

- تشغيل `powershell -NoProfile -File scripts/doctor-portal-release-check.ps1` على QA المحلي. السكربت يرفض أي API غير `127.0.0.1:56431`؛ لا نشر أو reset فيه.
- مركز من السجلات القديمة وطبيبان تابعان وحساب مستقل: دعوات، دخول بموبايل/إيميل، عزل الحالات، عزل الملفات والحساب المالي، وحساب موقوف.
- إنشاء حالة فيزيائية، تنسيق الاستلام حتى وصول المعمل؛ حالة ديجيتال بملف وأخرى برابط وصور؛ إعادة رفع بعد انقطاع دون حالة مكررة.
- شحنة جاهزة تستعمل عنوان ورقم الفرع. عنوانان مختلفان لا يجمعان في شحنة واحدة. خروج الشحنة يظهر بعد dispatch الحقيقي فقط.
- إرسال استفسار والرد عليه من الإدارة/المنسق.
- مقارنة الشهر الحالي والسابق بكشف المعمل. شاشة البوابة تعتمد الالتزامات المعترف بها والدفعات المعتمدة؛ حالات تاريخية بلا التزامات يجب مراجعتها قبل عرض الملخص، دون إصلاح مالي تلقائي.
- إعادة التقرير بالقراءة فقط: أعداد ومجاميع الطلبات والالتزامات والدفعات والتخصيصات والتسويات يجب ألا تتغير بسبب تطبيق تعريفات البوابة.

بعد نجاح هذه النقاط، يوصى بإطلاق محدود لمركز وطبيبين، ثم توسيع الدعوات. ETA وOTP وتطبيق الموبايل مؤجلة حسب قرار المالك.
